Chat Summary — Hotspot / Captive Portal / QR (Flutter)

1. Your Goal

Phone A runs a Flutter app, enables a Wi-Fi hotspot, and hosts a local offline webpage via a Dart HttpServer. Phone B scans a QR to join the hotspot and should automatically open a captive-portal webpage served by Phone A (fully offline).

2. Key Captive Portal Rules

  • Captive portal is triggered only when the hotspot has no upstream internet (Phone A mobile data must be OFF).
  • Hotspot still provides DHCP, gateway IPs and local connectivity even with mobile data off.
  • Phone B automatically performs connectivity checks and sends requests to the gateway (Phone A).

3. Server Requirements (Phone A)

Your Flutter/Dart HttpServer must:

  • Bind to 0.0.0.0 (use InternetAddress.anyIPv4) so hotspot clients can reach it.
  • Preferably listen on port 80 (required for iOS captive detection).
  • Return HTTP 200 with a small HTML body for captive-check paths:
/generate_204
/hotspot-detect.html
/ncsi.txt
/connecttest.txt
/

Ignore the Host header — clients will request external hostnames (e.g. captive.apple.com) and your server must still reply with the portal HTML.

Example minimal response:

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<html><body>OK</body></html>

4. Port Behavior & Compatibility

  • Android → Android: often works even if your server uses port 8000 (Android is flexible).
  • Android → iOS: iOS only checks port 80 for captive detection — if your server is on 8000, iOS will not auto-open captive portal.
  • Therefore, to support iOS you must ensure captive responses are available on port 80.

5. Why iOS Might Not Open Captive Portal

  • iOS strictly checks http://captive.apple.com/hotspot-detect.html on port 80 only.
  • If server runs only on 8000, iOS will not see the portal and will not open the captive UI.

6. Common Reasons Android Also May Not Open Portal

  • Server bound only to localhost instead of 0.0.0.0.
  • Server running on a port the hotspot implementation blocks.
  • Using Android LocalOnlyHotspot API instead of the system hotspot — local-only mode may not route captive-checks.
  • Server returns 204 or 404 (must return 200 + HTML).
  • App got backgrounded and server stopped — keep it foregrounded or use a foreground service on Android.
  • Client cached previous connectivity state (fix: Forget network → reconnect).

7. Manual Tests (Debugging)

  1. On client (Phone B), open browser and visit http://<gateway-ip>/ (gateway usually 192.168.43.1 on Android). If you see your HTML page, the server is reachable.
  2. Test specific path: http://<gateway-ip>/generate_204 or /hotspot-detect.html.
  3. Check server logs for incoming requests like GET /generate_204 or GET /hotspot-detect.html.
  4. If no requests appear: ensure hotspot is the system tethering hotspot and the server is bound to 0.0.0.0.

8. Recommended Working Setup

  • Phone A: Android device, Hotspot ON, Mobile Data OFF, Flutter HttpServer bound to port 80 (or port 80 responder + content on 8000), app foregrounded.
  • Phone B: Android or iOS client — scan QR and join hotspot; captive portal opens automatically if server responds correctly.

9. Wi-Fi QR Format

WIFI:T:WPA;S:SSID_HERE;P:PASSWORD_HERE;;

10. Things You Cannot Do

  • Normal apps cannot programmatically enable the system Personal Hotspot (iOS) or reliably toggle tethering without special privileges on Android.
  • You cannot force captive portal open if hotspot has upstream internet (the OS will not trigger it).
  • LocalOnlyHotspot often won’t trigger captive-detection consistently.

11. Practical Notes & Alternatives

  • If binding to port 80 fails on the phone (OEM restriction), iOS captive portal cannot be triggered — consider external hardware (ESP32 / Raspberry Pi) as AP for guaranteed behavior.
  • Alternative: use a tiny hosted loader page + payload-in-fragment approach (requires internet for loader fetch) — useful as a fallback.
  • For production reliability across iOS devices, prefer dedicated AP hardware or ensure your phone can bind to port 80 and remain foregrounded.

12. Quick Checklist to Get It Working

  1. On Phone A: Turn mobile data OFF, enable system Hotspot, keep Flutter app foregrounded.
  2. Start HttpServer bound to 0.0.0.0, preferably port 80.
  3. Make server return HTTP 200 and small HTML for captive paths and for any host header.
  4. Display QR: WIFI:T:WPA;S:SSID;P:PASS;; for Phone B to scan.
  5. On Phone B: Join hotspot, Forget & reconnect if needed, captive portal should auto-open.
