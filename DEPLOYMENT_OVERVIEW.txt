🚀 DEPLOYMENT FLOW
═══════════════════════════════════════════════════════════════════════════

STEP 1: Build Flutter App
   ┌─────────────────────────────────────┐
   │  $ ./deploy.sh                      │
   │  (or: flutter build web --base-href /app/)
   └─────────────────────────────────────┘
                    ↓
   Builds Flutter to: build/web/

STEP 2: Copy to Dist
   ┌─────────────────────────────────────┐
   │ deploy.sh copies: build/web → dist/app/
   └─────────────────────────────────────┘
                    ↓
   dist/ is now ready to deploy

STEP 3: Upload dist/ to Server
   ┌─────────────────────────────────────┐
   │ rsync / FTP / Git / Docker / etc.   │
   │ Upload: dist/ → your-server:/root/ │
   └─────────────────────────────────────┘
                    ↓
   Live at: your-domain.com


🌐 URL ROUTING AFTER DEPLOYMENT
═══════════════════════════════════════════════════════════════════════════

User visits: your-domain.com/
                    ↓
          Server checks: Does / exist?
                    ↓
          YES → Serves: dist/index.html (Landing Page)

User visits: your-domain.com/app/
                    ↓
          Server checks: Does /app/ exist?
                    ↓
          YES → Serves: dist/app/index.html (Flutter App)

User visits: your-domain.com/app/main.dart.js
                    ↓
          Server serves: dist/app/main.dart.js (App Code)


📁 WHAT TO UPLOAD
═══════════════════════════════════════════════════════════════════════════

✅ dist/                          ← The entire dist folder
   ├── index.html                 ← 20 KB
   ├── app/                       ← 3-5 MB total
   │   ├── index.html
   │   ├── main.dart.js           ← Largest file (3.3 MB)
   │   ├── flutter_*.js           ← Bootstrap & service worker
   │   ├── canvaskit/             ← 2-3 MB (WebAssembly)
   │   └── assets/                ← Images, fonts, data
   └── [optional: server.js for Node.js hosting]

❌ DON'T upload:
   • build/ or build/web/
   • lib/ (source code)
   • .dart_tool/
   • pubspec.lock
   • node_modules/
   • .git/


⚡ QUICK COMMANDS
═══════════════════════════════════════════════════════════════════════════

Local Testing:
  $ cd dist && node server.js
  → Visit: http://localhost:3000/

Update Flutter App:
  $ ./deploy.sh
  → Rebuilds and updates dist/app/

Deploy to Server:
  $ rsync -avz dist/ user@server.com:/var/www/cpft/

View Structure:
  $ ls -lah dist/
  $ ls -lah dist/app/


🎯 KEY POINTS
═══════════════════════════════════════════════════════════════════════════

✓ Landing page at ROOT (/) for SEO
  - Static HTML, loads instantly
  - Contains all marketing content
  - Links to /app/ for the interactive app

✓ Flutter app at /app/ subfolder
  - Completely separate from landing page
  - All assets served from /app/
  - Uses service workers for offline support

✓ ONE command to update everything:
  ./deploy.sh

✓ Server needs ONLY the dist/ folder
  - Nothing else needs to be deployed
  - Can use any web server (Nginx, Apache, Vercel, etc.)

✓ SPA Routing works automatically
  - Server rewrites /app/* to /app/index.html
  - Flutter app handles all internal routing
